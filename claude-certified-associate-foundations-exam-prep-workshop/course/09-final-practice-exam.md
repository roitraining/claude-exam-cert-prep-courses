# Rapid Review: Domains 1 to 4

| Domain | Exam Scenario | Correct Associate Decision | Common Trap to Avoid |
| :--- | :--- | :--- | :--- |
| **D1: Prompting (14%)** | Complex multi-part business request produces shallow output | **Decompose** into sequential steps and specify role, context, audience, constraints, and examples | Sending one vague, overloaded prompt or repeating “make it better” |
| **D2: Evaluation (21%)** | Claude confidently cites a specific regulation subsection for compliance | **Verify the cited subsection against the official regulation text** before sharing | Sending as-is due to high confidence, or asking Claude to rate its own confidence |
| **D2: Output Formats** | Need a standalone, editable report or template alongside chat | Render in **Artifacts** (use structured tables for comparisons; inline for quick replies) | Dumping a long standalone deliverable only as unstructured chat prose |
| **D3: Models and Features (12%)** | High volume of short customer-reply drafts where speed and cost matter | Select a **faster, lower-cost model (Claude Haiku)** | Using the highest-cost model (Opus) for every routine reply or disabling features |
| **D3: Context Limits** | Switching to an unrelated topic or continuing a very long thread | **Restart** a new chat for new topics; **summarize** a handoff block for long threads; **persist** recurring docs in **Projects** | Keeping 5 unrelated projects in one giant conversation thread |
| **D4: Workflow Design (16%)** | Process needs automated nightly REST API database sync or multi-agent code | **Escalate** custom API/code work to **Claude Developers** and enterprise systems to **Claude Architects** | Trying to build production API integrations manually inside chat |

# Rapid Review: Domains 5 to 7

| Domain | Exam Scenario | Correct Associate Decision | Common Trap to Avoid |
| :--- | :--- | :--- | :--- |
| **D5: Configuration (12%)** | Team needs consistent tone, templates, and reference docs across chats | Configure a **Claude Project** with system-level instructions and curated knowledge files | Re-pasting guidelines manually in every chat or uploading conflicting policy versions |
| **D5: Maintenance** | Company updates its annual pricing or HR policy | **Remove superseded files**, upload the current version, update instructions, and inform the team | Leaving both old and new policy PDFs in the same Project knowledge base |
| **D6: Governance and Privacy (15%)** | Analyzing a spreadsheet that contains customer names and account numbers | **Remove or anonymize personal identifiers before uploading**, consistent with policy | Uploading as-is because it is internal, or instructing Claude “do not retain this data” |
| **D6: Responsible Use** | High-stakes legal, compliance, HR, or financial deliverable | Keep a **qualified human in the loop** to review and approve before release | Allowing unreviewed AI output to make final regulated or personnel decisions |
| **D7: Troubleshooting (10%)** | Output formatting is inconsistent across runs despite detailed prose rules | Add **1 to 2 concrete few-shot examples** showing the exact target structure | Writing longer paragraphs of abstract instructions without examples |

# Final Exam-Day Checklist

### Before Launching Pearson VUE
- Confirm your government-issued photo ID matches your registration name exactly
- Clear your workspace of notes, phones, smart watches, and secondary monitors
- Remember the passing standard: **720 on a 100 to 1,000 scale** across **60 items in 120 minutes**

### Deconstructing Every Associate Question
- **Check verification and privacy first**: Does this output contain a citation or claim that must be checked against an authoritative source? Does the input contain PII that must be anonymized before upload?
- **Check fit and proportionality**: Which feature (**Project**, **Artifact**, **research mode**, **chat**) and model (**Haiku**, **Sonnet**, **Opus**) match the task’s speed, cost, and reasoning needs?
- **Check the role boundary**: Can this be solved with built-in Claude features, or should it be **escalated** to a Claude Developer or Architect?
